# ShopMind Enterprise：企业级 AI 智能导购系统 PRD

> **产品灵魂定位 (Product Vision)** ShopMind 并不是一个简单的聊天机器人，而是一套以自然语言为交互入口、以 Agent 为决策核心、以企业业务系统为能力底座的 AI 智能导购平台。

## 1. 项目背景 (Background)

传统电商的 GUI 交互模式存在信息过载与操作路径过长的问题，且传统的客服机器人依赖“关键词与决策树”，缺乏语义理解与业务执行力。 本项目旨在突破传统限制，构建一个具备**长期记忆、防幻觉机制与底层业务执行能力**的 AI Agent 系统。通过自然语言交互，系统不仅能理解复杂的复合导购需求，还能直接调度底层电商 API 完成下单、付款、查单等闭环操作，最终沉淀为一套可复用的企业级 AI 应用架构。

## 2. 目标指标 (Target Metrics)

*(注：以下指标为系统设计目标，将通过压测与实际上线运行后动态更新验证)*

- **TTFT (首字响应时间)**：目标 ≤ 1s（通过 Spring WebFlux + SSE 流式管道支撑）。
- **Token 消耗优化**：目标降低 30%（通过分层记忆与摘要机制测试验证）。
- **Tool 调用准确率**：目标 ≥ 95%（在 100 轮包含干扰意图的自动化测试中验证）。
- **高并发数据一致性**：目标 100%（在模拟高并发付款压测下，无超卖、无脏读，通过 CAS 乐观锁验证）。

## 3. 核心用户故事 (User Story)

**场景：老用户“小王”的二次复购与售后咨询**

- **已知条件**：小王，预算敏感受众，之前在平台购买过 AirPods。
- **交互链路**：
  1. **用户**：“我想买个平板，预算 3000 左右，最好和我的耳机是一个牌子的。”
  2. **Intent & Planner**：系统识别出【商品推荐】意图，并规划任务链路。
  3. **Memory**：从长期记忆中提取“曾购买 AirPods，偏好 Apple 生态”。
  4. **Tool (Search)**：Agent 自动将“3000元”、“平板”、“Apple”映射为参数，调用底层搜索工具。
  5. **Recommendation**：返回二手/翻新 iPad 或基础款 iPad 数据，生成流式推荐话术。
  6. **用户**：“行，就买推荐的第一个，直接帮我付款吧。”
  7. **Tool (Payment)**：Agent 抽取商品信息，调用 `createOrder` 和 `confirmPayment`，底层触发防超卖锁。
  8. **业务线**：订单状态流转为“已付款”，系统返回成功。
  9. **用户**：“对了，这个平板支持七天无理由退货吗？”
  10. **Knowledge (RAG)**：系统向量检索本地《售后政策.md》，准确回答退换货规则，拒绝 LLM 幻觉编造。

## 4. 全局 AI Workflow (工作流)

系统不仅是一个单一大模型，而是一套严密的流水线： `User Input` ↓ `Intent Understanding (意图网关)` ↓ `Planner (任务规划与路由)` ↓ `Memory (长短期上下文提取与注入)` ↓ `Knowledge (RAG 向量召回防幻觉)` ↓ `Decision (LLM 推理决策)` ↓ `Tool/MCP (业务接口参数映射与调用)` ↓ `Business Service (MySQL/Redis 业务状态流转)` ↓ `Response (SSE 流式输出)` ↓ `Memory Update (异步摘要与快照更新)`

## 5. 项目边界 (Scope)

**In-Scope（必须实现的核心架构）：**

- 基于 Agent 的意图路由与多工具调度（搜索、比价、推荐）。
- 基于分层设计的上下文对话记忆（Session & Long-term）。
- 基于 RAG 的企业本地知识库精准问答。
- 支持完整的电商订单状态机流转与防并发锁控制。

**Out-of-Scope（坚决不做，保障工程聚焦）：**

- 不接入真实的第三方支付网关（微信/支付宝等）。
- 不接入真实的物流轨迹流转（仅做节点模拟）。
- 不开发复杂的后台 CMS 页面，全力聚焦 AI 引擎与核心业务链路。

## 6. 演进路线 (Roadmap)

为保证系统稳步落地，开发计划划分为以下 Milestone：

- **v1.0 (MVP 阶段)**：跑通底层 Spring Boot + 大模型基础对话 + 纯数据库 CRUD。
- **v2.0 (Agent & Workflow 阶段 - 当前重点)**：完成 Tool 调度机制，实现商品搜索、比价、下单付款的 Agent 化闭环。
- **v2.1 (Memory 阶段)**：重构记忆体系，引入 MongoDB 实现滑动窗口与多租户上下文隔离。
- **v2.2 (Knowledge 阶段)**：接入 RAG，实现售后政策防幻觉。
- **v2.3 (MCP 阶段)**：解耦 Tool，构建标准化的企业内部能力调用协议。
- **v2.4 (Evaluation 阶段)**：构建大模型输出评估与自动化测试链路。
