## 2. 修正方式

### 2.1 新增 `BenchmarkConfigHolder`（ThreadLocal 机制）

**文件**：`pipeline/BenchmarkConfigHolder.java`

在 `BenchmarkRunnerImpl.executeAndCollectTrace()` 中：
- 开始时：`BenchmarkConfigHolder.set(config)` — 注入当前实验配置
- 结束时：`BenchmarkConfigHolder.clear()` — 清理（doFinally 覆盖所有路径）

Adapters 在 `buildRequestBody()` 中：
- `BenchmarkConfigHolder.get()` — 读取实验参数
- 降级：`get()` 返回 null 时使用 `application.yml` 默认值（非 Benchmark 场景）

### 2.2 修正 DeepSeekChatAdapter

| 参数 | 修正前 | 修正后 |
|------|------|------|
| model | `@Value` from yml | `config.llmProvider()` → fallback to yml |
| temperature | 硬编码 `0.1` | `config.temperature()` → fallback `0.1` |
| top_p | NOT sent | `config.topP()` → sent |
| max_tokens | NOT sent | `config.maxTokens()` → sent (if not null) |
| seed | `@Value` from yml | `config.seed()` → fallback to yml |

### 2.3 修正 DashScopeChatAdapter

| 参数 | 修正前 | 修正后 |
|------|------|------|
| model | `@Value` from yml | `config.llmProvider()` → fallback to yml |
| temperature | 硬编码 `0.1` | `config.temperature()` → fallback `0.1` |
| top_p | NOT sent | `config.topP()` → sent |
| max_tokens | NOT sent | `config.maxTokens()` → sent (if not null) |
| seed | N/A | 明确记录：Qwen 不支持 seed |

### 2.4 修正 BenchmarkConfig

- 新增 `maxTokens` (Integer) 字段，可为 null
- `hyperparameterEntries()` 包含 `maxTokens`

### 2.5 修正 ExperimentReport

- 新增 `effectiveParameters` (Map<String, Object>) 字段
- `finalize()` 中从 BenchmarkConfig 派生并记录所有生效参数
- 新增 `getEffectiveParameters()` getter
